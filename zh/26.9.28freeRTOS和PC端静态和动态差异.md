# 26.9.28 FreeRTOS 与 PC 端：静态 vs 动态内存

> 学习笔记。起点问题：所谓"静态"，只是指函数在编译和运行时的内存都不会释放吗？
> 结论先放这：**对了一半，但"静态"的对象是"数据"不是"函数"。**

## 一、起点问题：我的理解哪里对、哪里错

我原以为"静态"= 编译和运行时内存都不释放。这个理解对了一半，错在**对象搞混了**——把"函数代码"和"数据"当成了一回事。

## 二、C 语言里"静态"的两层含义

| 对象 | 存储位置 | 生命周期 |
| :--- | :--- | :--- |
| 函数代码 | `.text` 段 | 程序启动到结束，永远存在 |
| 静态变量 | `.data` / `.bss` 段 | 程序启动到结束，永远存在 |
| 局部变量 | 栈 | 函数调用到返回 |
| 动态分配 | 堆 | malloc 到 free |

关键澄清：**函数代码本身**放在 `.text` 段，确实从启动到结束都存在、不会"释放"——但这不是 FreeRTOS 说的"静态"，因为**所有代码都这样**，不管你是不是静态创建。

**FreeRTOS 的"静态"指的是数据**：任务控制块（TCB）和栈，由用户提供，放在 `.bss` / `.data` 段，生命周期贯穿整个程序。

## 三、FreeRTOS 的两种创建方式

| 方式 | API | 内存来源 |
| :--- | :--- | :--- |
| 动态创建 | `xTaskCreate()` / `xQueueCreate()` | 从 FreeRTOS 堆（heap_1~heap_5）分配 |
| 静态创建 | `xTaskCreateStatic()` / `xQueueCreateStatic()` | 用户**预先提供**一块内存 |

静态创建的写法：

```c
// 用户自己定义任务控制块和栈
StaticTask_t xTaskBuffer;
StackType_t  xStack[128];

xTaskCreateStatic(
    vTaskCode,       // 任务函数
    "NAME",          // 任务名
    128,             // 栈深度
    NULL,            // 参数
    1,               // 优先级
    xStack,          // 用户提供的栈
    &xTaskBuffer     // 用户提供的 TCB
);
```

关键点：`xStack` 和 `xTaskBuffer` 是用户定义的全局/静态变量，**生命周期由 C 语言决定，不由 FreeRTOS 堆管理器决定**。

## 四、静态 vs 动态：核心区别

| | 静态创建 | 动态创建 |
| :--- | :--- | :--- |
| 内存来源 | 用户定义的全局/静态数组 | FreeRTOS 堆（pvPortMalloc） |
| 内存释放 | 不能释放，除非程序结束 | 可 vTaskDelete() 释放 |
| 内存大小 | 编译时确定 | 运行时从堆分配 |
| 确定性 | 完全确定，无堆碎片 | 依赖堆管理器，可能有碎片 |
| 适用场景 | 安全关键系统（汽车、医疗、航天） | 通用嵌入式系统 |
| 配置宏 | configSUPPORT_STATIC_ALLOCATION = 1 | configSUPPORT_DYNAMIC_ALLOCATION = 1 |

## 五、为什么要有静态创建：确定性

因为**安全关键系统不允许动态内存分配**：

- **汽车 ECU**：任务创建必须在编译时确定，不能运行时失败
- **医疗设备**：不允许堆碎片导致崩溃
- **航天器**：内存必须完全可预测

静态创建的代价：你必须手动管理这些内存，不能"用完就删"。

## 六、和 PC 端（Linux）对照

| | Linux | FreeRTOS |
| :--- | :--- | :--- |
| 动态分配 | kmalloc() / vmalloc() | pvPortMalloc() |
| 静态分配 | static struct task_struct init_task | xTaskCreateStatic() |
| 内核栈 | 动态分配（alloc_thread_stack_node） | 静态数组或堆分配 |
| 典型场景 | 通用系统，动态创建进程/线程 | 安全关键系统，静态创建任务 |

有意思的对照：Linux 的 `init_task` 就是一个**静态定义的任务结构体**，思路和 FreeRTOS 静态创建一样——内核最早的根进程，同样需要"编译时就确定、不需要运行时分配"。

## 七、一句话总结

> FreeRTOS 的"静态"指的不是函数代码，而是任务/队列的**数据**（TCB 和栈）由用户预先提供，放在 `.bss` / `.data` 段，生命周期贯穿整个程序、不能释放。它和 C 语言的 `static` 关键字有交集，但不完全一样。静态创建的核心价值是**确定性**——没有堆分配、没有碎片、没有运行时失败。
