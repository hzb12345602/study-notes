# 26.11.19 单片机内存、计算机内存与存储区分

> 学习笔记。主线：单片机内存 vs 计算机内存 vs 存储区的区别。
> 铺垫：从 16 位寄存器操作 → 硬件寻址 → 芯片与 CPU 层级 → ASIC，最后落到内存。
> 起点问题：手册给的 16 位寄存器 `0x0001`（4 位十六进制），是不是也能直接操作硬件？

## 一、铺垫：16 位寄存器与 0x0001

**1 个十六进制字符 = 4 个二进制位**，所以 4 位十六进制 = 16 位：

```
0x0001  ->  0000 0000 0000 0001
0x000A  ->  0000 0000 0000 1010
```

直接操作硬件：

```c
*(volatile uint16_t *)0x40010800 = 0x0001;
```

```verilog
reg [15:0] my_reg = 16'h0001;
```

编译器/综合器不管几进制，最终翻译成 16 根数据线的电平：第 0 根高，第 1~15 根低。

**为什么写满 4 个 0**：对齐位宽，防踩坑。写 `0x1` 看不出是 8 位还是 32 位；写 `0x0001` 一眼看出 16 位。Verilog 用 `16'h0001` 同理。

**位宽陷阱**：8 位寄存器收到 `0x0001` 会截断成 `0x01`；32 位寄存器会自动补 0 扩展。

## 二、铺垫：16 位信号怎么找到硬件（火车线路比喻）

寻址的本质是**分流**：

| 硬件 | 火车比喻 |
| :--- | :--- |
| 地址总线 | 16 条并排铁轨 |
| 高低电平 | 道岔的开/关状态 |
| 地址译码器 | 调度中心（2¹⁶ = 65536 个出口） |
| 片选信号 CS | 被点亮的站台 |
| 数据总线 | 驶入站台的火车 |

输入 `0x0001` → 译码器组合逻辑导通 → **只有 1 号出口拉高**，其余 65535 个全 0 → 只有对应外设的片选被拉高，其他外设"闭目养神"。

Verilog 里的译码器：

```verilog
always @(*) begin
    if (addr == 16'h0001)       gpio_cs = 1'b1;
    else if (addr == 16'h8000)  sram_cs = 1'b1;
    else begin
        gpio_cs = 1'b0;
        sram_cs = 1'b0;
    end
end
```

综合出来就是一堆 LUT——物理上就是"判断 16 根线电平组合的道岔开关"。

**16 位地址的极限**：最多寻址 2¹⁶ = 64KB。要更大内存就多级寻址：高位选 Bank（城市），低位选偏移（街道门牌）。

## 三、铺垫：芯片 vs CPU，在软硬件层级的位置

**结论：CPU 是"逻辑与指令的大脑"，芯片是"物理与电路的躯壳"。CPU 一定是芯片（或芯片的一部分），但芯片不一定是 CPU。**

| 层级 | 核心对象 | 日常操作 |
| :--- | :--- | :--- |
| 应用层 | 业务逻辑、算法 | C++、Python、Shell |
| 系统层 | 操作系统 | Linux 内核、调度、虚拟内存 |
| 指令层 (ISA) | 汇编指令集 | RISC-V、x86、syscall |
| 微架构层 | **CPU（状态机）** | 取指、译码、执行、访存、写回 |
| 逻辑层 | RTL / 逻辑门 | Verilog 写的 FIR、ALU、状态机 |
| 物理层 (Chip) | **芯片（硅片+晶体管）** | 7nm/5nm 流片 |

一次贯穿：`int a = b + c;` → RISC-V `add a0,a1,a2`（指令层）→ ALU 使能（微架构层）→ 触发器与门电路（逻辑层）→ 硅片晶体管（物理层）。

**比喻**：芯片 = 城市地基；CPU = 行政中心；FPGA = 万能积木地皮（盖成行政楼就是 CPU，盖成厂房就是加速器）；软件 = 送到办公桌上的公文。

## 四、铺垫：ASIC 是物理固化的极致

| 类型 | 比喻 | 能否软件改功能 |
| :--- | :--- | :--- |
| CPU | 手动挡汽车 | 能，软件决定怎么开 |
| FPGA | 乐高底盘 | 能，重新拼（重新烧录） |
| ASIC | 出厂焊死用途的专用车 | 不能，功能固化 |

三个关键细节：
1. **功能固化，但参数可调**：ASIC 内部仍有外设寄存器，CPU 可通过 I2C 等总线调音量、采样率等
2. **为什么造 ASIC**：极致性能、极低功耗（0.1W vs CPU 的 100W）、极低量产单价
3. **Verilog → ASIC**：你写的 RTL 逻辑验证通过后，就是流片（Tape-out）的物理图纸

## 五、核心：单片机内存——变量存在哪

需求：变量少时直接用 CPU 寄存器（纳秒级）；变量多时开辟内存（SRAM）。

**物理分布（以 STM32 为例）**：地址 `0x20000000` 开始的区域，物理上就是芯片内集成的 **SRAM**（几十~几百 KB）。

| 变量类型 | 存放位置 |
| :--- | :--- |
| 全局变量 / 静态变量 | `.data` / `.bss` 段 → SRAM 固定地址 |
| 局部变量 / 函数调用 | 栈 Stack → SRAM（SP 向下压） |
| 动态分配 | 堆 Heap → SRAM 切出来（FreeRTOS 的 `ucHeap` 本质是 SRAM 里的静态大数组） |

查证方法：编译后看**链接器生成的 `.map` 文件**，里面列出每个变量的物理地址。

## 六、核心：计算机内存——为什么单片机用 SRAM、PC 用 DRAM

| | SRAM | DRAM |
| :--- | :--- | :--- |
| 结构 | 6 个晶体管/位 | 1 管 + 1 电容/位 |
| 速度 | 极快（与 CPU 同频） | 较慢 |
| 刷新 | 不需要 | 电容漏电，需不断刷新 |
| 面积/成本 | 大 / 高 | 小 / 低 |
| 容量 | 小 | 巨大 |
| 典型用途 | 单片机内内存、**CPU Cache** | PC 内存条（16GB/32GB） |

**关键串联**：PC 里的 SRAM 去哪了？→ 变成了 CPU 内部的 **L1/L2/L3 Cache**。PC 读数据，其实是 SRAM 在缓存 DRAM 里的数据。

**FPGA 的 BRAM 物理本质也是 SRAM**——和你用 C 声明 `uint8_t buf[1024]` 是同一类物理承载。

## 七、核心：存储区分——内存 vs 存储、易失 vs 非易失

| 层级 | 介质 | 易失性 | 用途 |
| :--- | :--- | :--- | :--- |
| 寄存器 | 触发器 | 易失 | CPU 直接操作数 |
| SRAM | 6 管/位 | 易失 | 缓存、单片机内内存 |
| DRAM | 1 管+1 电容 | 易失 | 主存 |
| Flash | 浮栅晶体管 | **非易失** | 代码、常量 |
| SSD/HDD | 闪存/磁盘 | **非易失** | 外存、大容量 |

**"内存"和"存储"的区别**：内存（SRAM/DRAM）断电即失、用来"跑程序"；存储（Flash/SSD/HDD）断电保留、用来"放程序"。

**单片机内存不够的解法**：
1. 常量数组加 `const` → 编译器放 **Flash**，只读不占 RAM
2. 外挂 SDRAM → 通过 FSMC/FMC 总线映射大数组
3. 优化算法，少开大数组，用指针和循环缓冲

## 八、总结：一条完整知识链

> **需求**（变量多、要存大数组）→ **软件层**（C 申请栈/堆/全局）→ **编译层**（链接器分配到 `0x20000000`）→ **硬件层**（地址总线寻址到 SRAM 矩阵）→ **电路层**（SRAM 内部 6 管触发器阵列锁存电平）。

能把"软件里算出的内存大小"和"物理上的 SRAM 颗粒"直接挂钩，就跨越了软硬割裂的鸿沟。
