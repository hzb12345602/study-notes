# rust初学有感26.9.16 自举：一门语言的成人礼

> 学 Rust 时的一个灵感：一门编程语言正式出现的标志，是不是能够自举？
> 本文记录：原始想法 → 修正后的理解 → 它和所有权/生命周期的关系。

## 一、原始灵感

正在学 Rust，刚了解所有权和生命周期。我突然想到：新的编程语言，类似于当初从汇编写出 C 语言——**一门语言正式出现的标志，是它能够自举（self-hosting）**。当一门语言能用自己写自己的编译器，就意味着一个新的生态有了基础。

## 二、修正：自举是"成年礼"，不是"出生证"

这个想法方向对，但"正式出现的标志"这个说法不准——很多极其成功的语言至今不自举：

| 语言 | 自举情况 | 备注 |
| :--- | :--- | :--- |
| C | 1973 | Ritchie & Thompson 用 C 重写 Unix 内核和 C 编译器本身 |
| Rust | 约 2011 | 最初用 OCaml 写，后自举 |
| Go | 2015（1.5 版） | 最初用 C 写，1.5 版才自举 |
| Python | 未完全自举 | CPython 用 C 写；PyPy 自举但非主流 |
| JavaScript | 未自举 | V8 引擎用 C++，但生态极其庞大 |
| C++ | 较晚 | 早期 Cfront 依赖 C 编译器 |

所以更准确的说法是：

- **语言的"出生"** = 第一个能跑通 Hello World 的编译器
- **语言的"成年"** = 它能自己编译自己（自举）

自举不是"出生证"，是"成年礼"。

## 三、自举最值钱的地方：生态的"信任锚"

我原话说"自举意味着生态有了基础"，这句话其实比"正式出现"更准。

自举的深层意义不只是技术，更是**信任**：

- **对开发者**：编译器作者都愿意用这门语言写编译器，说明他们真的相信它
- **对社区**：自举后，想贡献代码的人只需要学这一门语言，不用同时懂 C 或 OCaml
- **对生态**：标准库、包管理器、构建工具都能用同一门语言写，形成正反馈循环

Rust 就是最好的例子：`rustc`、`cargo`、`rust-analyzer` 全用 Rust 写。整个工具链自洽，新贡献者只学 Rust 就够——这就是"生态有了基础"的真正含义。

## 四、自举的代价

- **引导问题（bootstrapping problem）**：第一个 Rust 编译器必须用 OCaml 写，再逐步用 Rust 重写。过程是 stage0 → stage1 → stage2，非常痛苦
- **信任链**：如果编译器有 bug，可能错误地编译自己，把 bug 固化。这是为什么 Rust 有 miri 解释器和形式化验证项目
- **可移植性**：自举后，移植到新平台必须先有能跑该平台的编译器，比 C 写的编译器更难移植

## 五、为什么 Rust 的自举比 C++ 的更有意义

我现在学的**所有权和生命周期，恰恰是 Rust 能"安全自举"的关键前提**：

- C++ 能自举，但编译器代码里充满 `new` / `delete` 和裸指针，容易出内存 bug
- Rust 的所有权系统在**编译期**就杜绝了内存错误 → `rustc` 本身的可靠性远高于早期 C++ 编译器
- 所以 Rust 的自举不只是"用自己写自己"，而是"**用安全的自己写安全的自己**"

## 六、一句话总结

> 自举是语言的"成年礼"，不是"出生证"。它证明语言有表达力、社区有承诺、生态有独立基础。而我学的所有权和生命周期，正是 Rust 能安全自举的地基——这也是区分"会用 Rust"和"懂 Rust 为什么这样设计"的分水岭。
