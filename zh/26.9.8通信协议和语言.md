# 26.9.8 从 UART 到语言：所有通信都是"预先约定"

> 源自一次闲聊：大一自己约定的 UART 协议，串起了机器码、密码学和语言。

## 原始火花

大一的时候我自己约定过一个用 UART 传数据的协议——自己定波特率、帧格式、命令字。回头看，我当时干的活，和更早的工程师约定机器码来操作硬件、再早的人靠密码学规则建立对话，本质上是同一件事。

## 类比链：五层不同的"约定"

| 例子 | 约定的是什么 | 约定失效会怎样 |
| :--- | :--- | :--- |
| UART 协议（大一的我自己） | 波特率、起始位/停止位、数据位、命令字 | 读到的全是乱码 |
| 早期机器码（拨开关） | 指令集手册：opcode 对照表 | CPU 把加法当减法，程序崩溃 |
| 密码学 | 密钥 + 算法 | 信息变噪音，无法解密 |
| 历史语境 | 特定时期的社会"公约" | 后人误读（"同志"被按现在的意思理解） |
| 语言方言 | 词汇表 + 语法 | 互相听不懂，没法协作 |

## 统一点：共享的对照表

任何"交互系统"的本质，都是两个实体之间**提前共享的一张对照表**。没有这张表，物理世界只是一堆无序的电磁波或声波——只有共享了约定，电平波动才变成指令，声波才变成概念。

## 但差异比统一更有意思

同一个框架下的这些例子，差别才是真正值得琢磨的：

- **UART / 机器码**：约定精确、可验证。出错是确定性的（就是乱码），没有商量余地
- **密码学**：核心不是可靠解码，是**限制谁能解码**——它关心的是安全语义，不是正确性语义
- **语言**：模糊、实时协商、能容错。双方可以边聊边校准，说错一个词还能靠上下文猜
- **历史解读**：根本不是"双方协议"，是**单向解读**——后人手里只有一份约定，还常常缺页

所以更准确的说法是：协议不是一种东西，而是一条**光谱**——一头是确定性的硬件时序（错一个 bit 就完蛋），另一头是不断协商演化的自然语言（错一半还能懂）。技术协议在往"精确"那端走，人类语言天生在"鲁棒"这端。

## 工程落点

做接口设计，本质就是**设计那张共享约定**，而约定的脆弱点在于：**一方改了，另一方不知道**。大一那次如果我只改波特率不通知接收端，收到的一定是乱码——约定没有版本协商，就是脆弱的。所以成熟协议都要有版本号、握手、协商机制，本质都是在解决"这张表会不会对不上"。

学 RISC-V 特权级切换、学 OSI 分层，也是同一件事：在不同"语境"之间切换不同的译码映射表。

## 一句话收尾

> 写协议的工程师、设计指令集的先驱、发明密码的人、创造语言的人类，做的是同一件事：**为了让两方能说话，先约好每一个符号的意思。**
